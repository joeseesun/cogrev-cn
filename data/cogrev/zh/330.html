《思科要在七层网络模型上加两层，让不同厂商的 AI 智能体共享意图》

思科内部有个叫 CAIPE 的系统，20 个智能体一起干活，替站点可靠性工程师处理云环境运维。成绩单是：团队负载降了 30%，40% 的任务被完全自动化，从问题出现到响应的时间，由小时级压到几乎即时。这套系统后来开源，社区名单里有 Adobe、AWS、Nike。

Vijoy Pandey 是思科 Outshift 的 SVP 和总经理，CAIPE 出自他的团队。他讲这套系统时语气平静，因为在他眼里，这只是一段“基础管道”。他想推的事更大：给互联网补一层专门供 AI 智能体使用的基础设施，让来自不同厂商、代表不同利益的智能体能够发现彼此、对齐意图、共享上下文，然后一起解决训练数据里没见过的问题。他管这个叫“认知互联网”，Internet of Cognition。

思科的老本行，是把东西摊开

用三个词概括思科，Vijoy 给的是“把信息搬来搬去”。底下有四根业务柱子：网络、安全、可观测性、协作。协作这条线就是 Webex。对做 AI 的听众，他更愿意换个角度介绍：思科是一家分布式系统公司，几十年干的事情是 scale out，把许多台机器连成集群。

这个定位很关键。当前 AI 的主旋律是 scale up，把模型做大、参数做多、单点能力做强。思科擅长的方向刚好相反，把能力摊到很多节点上。

网络里到底有多少靠机器学习跑，多少是死规则？Vijoy 把边界划得很清楚。数据平面是确定性的，路由表、交换机转发，这些不能交给概率。他的原话是，我和你之间的连接“不想留给运气”。但控制平面早就在用 ML 了：异常检测、流量预测，比如超级碗这种事件提前调度；也包括故障预测，盯住海底光缆和互联网咽喉点的风险；还有客户情绪分析、Webex 的降噪。这些都是跑了很多年的老管线。

真正开始变的是大模型进入企业之后。Project Jarvis 是 Outshift 最早跑起来的用例之一，思路是把写代码那一套智能体化搬到 SRE 流程上。

只往高里堆，漏掉了另一个轴

Vijoy 对 AGI 和 ASI 挑了一个偏技术的定义：一组智能体协作，解决一个训练数据里完全不存在的新问题，全程没有人类介入。他承认这个定义混了经济和技术的成分，但他愿意押这个。

然后他给了一个判断：整个行业只在一个轴上用力，垂直扩展。更大的模型、更强的推理器、更多数据、更多算力。另一个轴一直空着，水平扩展，让智能体学会“一起想”。

他用人类演化做类比。工具使用、符号沟通、画图、举旗，这些东西存在了几十万年，智能曲线一直平缓。大约 7 万年前语言出现，曲线跳出阶跃。原因不神秘：可以商量怎么打下那座山头的策略，可以把大任务拆成小任务、按专长分给不同的人，可以对意图达成一致，可以协调，可以执行。这套东西让人类能跨越距离和时间维持合作，最终建起全球文明。

Vijoy 的核心论点是：同样的轨迹正在硅基世界里重演，但缺了语言那一跃。今天的 AI 有越来越聪明的大脑，有子智能体，有自我委派，本质上还是“我脑子里再开几个子进程”。智能体之间没有真正的协作层。

“如果我们要把时间线往前拉，就必须动用第二个轴，水平扩展智能。这个轴今天完全空着。”

主持人 Nathan Labenz 补了一个观察。METR 的 Ajeya Cotra 最近写文章说，衡量 AI 任务时长的指标该改了。16 小时以内，一个人干和拆给多个人干差别不大，因为协调成本是固定的。任务拉长到几周，并行处理的优势才显出来。她建议用“一个组织良好的团队需要多久”当尺子。

Vijoy 接的是另一头：那把尺子量的还是一个 AI。他想要的是不同厂商、不同专长、不同模型的智能体之间的协作，因为那才是人类团队真正强的地方。

两个 AI 各干各的，人在中间当胶水

这集播客的准备过程本身就是案例。Nathan 用 Tasklet 做深度研究，搜集 Vijoy 的公开资料，再对照自己过去几百期的提问风格，起草问题清单。同一时间，Vijoy 团队里的 Rebecca 也用 AI 研究了 Nathan 和节目，整理出建议话题。两个智能体都完成得不错，但它们彼此不知道对方存在，产出通过电子邮件在人与人之间传递，最后由 Nathan 人工合成。

Vijoy 拆解了这个场景：Nathan 那个智能体带着 Cognitive Revolution 的历史做局部优化，他那边的智能体带着 Outshift 的内容做局部优化。两个 Venn 圆有交集，目标也一致，都是做出一期好节目。今天的让步是人类在做，比如“这个太营销了，收一点”。要自动化的是这层人类胶水，让两个智能体自己收敛到共同意图，并且把共享上下文留存下来，下次换嘉宾还能接着用。

医疗场景的演示更具体。一位病人打进来，需要根据病史、医生排班、保险档案被路由到对的科室。系统里有四个智能体：调度（医院自己的，负责和病人对话）、保险（付款方，第三方）、诊断（第三方）、药房（第三方）。只有调度属于医院。

这四个智能体原先互相说不上话。让它们协作，第一步是把它们发现、连接、赋权、拼装起来。思科一年前开源了 AGNTCY 项目，拼写 A-G-N-T-C-Y，属于 Linux 基金会，提供四根桩子：

  • 发现：一个智能体目录，按能力和声誉搜索，类似给智能体用的 DNS。底层架在分布式哈希表上，没人拥有这个目录。搜出来的结果可能是一个 API 端点，也可能是 Git 代码树里的智能体定义。
  • 身份与访问：这是最关键的一根桩子，后面细说。
  • 通信：智能体对工具走 MCP，也就是 Anthropic 的模型上下文协议；智能体对智能体走 A2A，Google 的协议。思科是这两个协议的基础成员。
  • 可观测性：和微软合作往 OpenTelemetry 里推扩展。服务活着，不代表智能体没发疯，两件事要分开看。

四根桩子搭完，四个智能体可以互相发消息了。今天能做的到此为止。消息的载荷是不透明的二进制块，里面装了什么没人知道。意图对齐、共享记忆、协调、谈判，这些灰色地带全靠人在中间当胶水。每个智能体有自己的局部优化目标：调度盯着响应时间，诊断盯着置信度，保险盯着 ROI。总得有人站出来说，你们都让一步，为了病人的全局结果。

这就是他提议给七层网络模型加两层的动机。L8 是语法层，解决“你在 Vertex 上建的智能体，和我在 LangGraph 或 Bedrock 上建的那个，怎么说话”的问题，框架不同，载荷格式不同，需要一层翻译。L9 是语义层，也叫认知状态层，往消息里塞一个元头部，标明“我现在是在发现信息，是在谈判，是在协调，还是准备执行一个工具调用”。

他举了 OpenClaw 的例子。一堆 OpenClaw 智能体凑在一起，全靠自然语言聊，聊得满天飞，没有在构建一致的状态。要进企业、要收敛、要产生建设性的涌现行为，就得给这团对话套点结构。

身份那根桩子，Vijoy 认为是当前部署完全自主智能体的最大障碍。现有体系是 RBAC，基于角色；后来补了 ABAC，基于属性。这两套都是给人和确定性机器设计的。机器不会今天当 Vijoy 明天当 Nathan。智能体会。

所以他提出 TBAC：Tool、Task、Transaction based access control，按工具、任务、交易授权。默认给最低权限，执行某个任务时临时提权，任务结束立刻收回，不给智能体长期权限。这套机制要能读 L9 的语义流，从对话里判断“这个智能体到底想干什么”，再决定给不给权限。等于说，L9 是 TBAC 的前置条件。

潜在空间该不该放开

回到开头那套 SRE 系统。CAIPE 现在接五个以上用户界面，跨云厂商、云原生环境、本地环境做一百多种工具调用，覆盖十多个工作流，二十个左右的智能体协同。指标前面说过：负载降 30%，四成任务全自动，响应从小时到即时。Vijoy 还提了一句团队士气，因为日常不再被琐事淹没。开源之后，社区里有 Adobe、AWS、Nike 这些企业成员在试。

有一个分歧值得单独说。Nathan 问，AI 用人类看不懂的方式交流，比如潜在空间、高速 token，会不会失控。他提到 Meta 有论文显示在潜在空间里推理，寻路任务表现更好；也提到 ChatJimmy.ai 把模型烧进硅片跑到每秒 15000 token，回 2000 token 只要六分之一秒，用起来有点震撼。

Vijoy 的回答跟很多安全派相反。他认为应该主动利用智能体不同于人的特性。人类没法发一个 API 调用，没有 KV cache 可以传，不能把潜在空间寄给对方。智能体可以。既然可以，为什么要让它走 tokenize、传输、detokenize 这条贵路？

“智能体像人，但它们也不像人。人没法发 API 调用。我可以把潜在空间寄给你，人做不到。智能体可以。那就利用这些人类不具备的属性，让它们比人更强。”

他设想了三种认知状态传输协议：语义状态转移，就是自然语言；潜在空间转移，直接传 KV cache，效率最高，但闭源模型厂商不开放；压缩状态转移，用于边缘设备，手机、笔记本、可穿戴设备和数据中心之间。

代价是可能发散、可能过度专业化、可能钻牛角尖。所以他配了“认知引擎”，概念来自图灵奖得主 Raj Reddy：一类是认知加速器，一类是守护天使。它们像会议里坐在角落记笔记的人，透明地观察智能体之间的对话，做摘要、做合规、做安全、防止发散。他还提到要用博弈论的框架去建模多智能体系统，把人类行为研究里那一大堆成果搬过来。

企业里的现实：多厂商共存，护栏是入场券

Nathan 追问护栏跟不跟得上。Vijoy 把问题翻了个面：企业不会部署护栏没想清楚的系统，所以护栏是入场券，没得选。而且企业环境里必然是多厂商智能体共存，ServiceNow、Salesforce、微软、OpenAI、Anthropic、Google、思科，每家都会有智能体进来，五年内不会有一个智能体干完所有事。互通是刚需。

去中心化和身份也是同一逻辑。谁控制目录，谁就控制声誉、安全、定价和背后的商业。思科在 AGNTCY 里把目录和身份都做成可去中心化的选项：目录架在分布式哈希表上，身份可以接 Okta、Duo 这些既有 IDP，也可以部署去中心化身份提供方。企业可以先从 Active Directory 起步，架构上留了开放的口子。

Nathan 在收尾时说了一句他反复讲的话：任何东西一旦过度集中就会变危险，毒品是这样，各种现象都是这样，过度集中的智能本身大概也危险。替代方案只能是分布式、有缓冲、网络化、更生态、至少在某些边缘开放且无需许可的系统。

明天就能用的几件事

第一，给智能体授权时，从“角色”切换到“任务”。问三个问题：它要用什么工具，它要完成什么任务，它要参与什么交易。默认最低权限，用完即收回。这套 TBAC 思路已经写在 AGNTCY 的开源规范里，可以直接拿来做内部权限设计。

第二，多智能体系统的验收指标，别只看消息通不通。四个智能体互相能发消息，只是基础管道。真正的分水岭是有没有共享记忆、有没有意图对齐、有没有全局目标的让步机制。做概念验证时把这三项单独列出来打分。

第三，去 agntcy.org 看一眼。四大支柱的架构图、代码、社区入口都在那。哪怕不采用，拿它当 checklist 对照自家智能体平台的缺口也划算。Outshift 官网还有那个医疗四智能体的可点击演示，能直观看到每个智能体的活动、意图、上下文和集体推理。

第四，把“自动化率”当成核心 KPI 来追。CAIPE 的 40% 不是笼统的效率提升，是明确划出来“这类任务我们不再管了”的边界。这个数字比“节省了多少人时”更能指导下一步往哪投。

第五，如果你的智能体要跨组织协作，现在就考虑 L8 和 L9。语法层的翻译，MCP 和 A2A 已有现成方案；语义层的意图标注还没有标准。早期参与标准讨论的成本，远低于后期改造。

Vijoy 最后留了一句：这不是科幻，路径已经在成形。20 个智能体接管四成运维是今天的现实，四家不同组织的智能体围着一位病人协作是今天的演示。缺的那一层，正在被补上。
