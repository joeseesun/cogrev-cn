《智能体干的活，八成本该是代码：Zapier CEO 谈AI自动化的真实水位》

40%。这是目前所有AI模型在 Zapier 自动化基准上的最高准确率。大约600道真实知识工作任务，覆盖营销、销售、HR、运营，最新登顶的 Astra（GPT-6）也就答对这么多。

出题的人，Zapier 联合创始人兼 CEO Wade Foster，2026年9月再上 Nathan Labenz 的播客《Cognitive Revolution》。18个月前他来的时候，Zapier 已有40万客户把超过1亿个任务交给AI处理，YC 总裁 Garry Tan 称它是「未来的AI知识工作者」。18个月后，模型换了几代，Zapier 造齐了 Agents、Chatbots、MCP 服务器、SDK、AI Guardrails 全家桶，主持人 Nathan 的总结却有点泄气：白领工作的变化，远低于他的预期。

Wade 补了一句，身边朋友家人的日子照旧，顶多拿 ChatGPT 配餐、规划旅行。但接下来这个来自客户数据的判断，比40分更扎心：客户用智能体干的活里，80% 其实应该交给老式的确定性代码。

人人都在找「日常驾驶座」

这18个月，Wade 最大的学习是一个使用习惯的固化：大多数人已经选定了自己的「日常驾驶座」（daily driver），可能是 Claude Code，可能是 ChatGPT，也可能是 Cursor。一天里大部分活都在这里面干。Wade 自己用的是 Cursor。

这个观察直接决定工具厂商的生死选择。一条路是把用户拉到自家平台上搭智能体，另一条是做「无头工具」（headless），把能力和数据送进用户已经选好的驾驶座。连 Salesforce 这样的老巨头也在转无头路线。

Wade 站得很明确：用户不会为你的平台搬家，你得把能力送到他每天待的地方。Zapier 的答案就是 MCP 服务器，把 Zapier 连接的应用和数据直接接进 Cursor、Claude Code 这些驾驶座。Nathan 问 Zapier 是不是要当所有驾驶座之上的「优步工具」，Wade 基本认了。他公司内部还有一个自研工具，带虚拟文件系统当上下文层，上面跑自动化和应用，他把它接进 Cursor 一起用。

播客里 Nathan 提到 Tasklet 创始人 Andrew Lee 的说法：最终只有三类软件公司能活，大家其实都在给模型造同一层东西，一层横在模型之上、提供工具和护栏的「机甲服」。Wade 认同其中一个判断：没人想被单一模型锁死。

证据就在他自己的基准里。Astra（GPT-6）40%最高分，但更贵；Gemini 3.7 分数略低，成本只有零头。企业要在任务层面反复权衡，简单任务用便宜模型，硬任务再上最强的。现代组织需要的是随时换模型的自由，也就需要有人帮它调度这些能力。模型公司有先发优势，但它们卖不了对手的 token，也管不了开源，中间总得有个第三方。

他同时提醒，驾驶座自己也能造工具了，但能造和该造是两回事，自己造的工具，维护、可靠性、在线率都得自己扛。应用层的创新远没结束，只是形态变了：上个十年是 SaaS 爆发，这一轮是无头工具的爆发。

600道题考40分，八成活儿该交给代码

Automation Bench 考什么？Wade 在节目里念了一道真题：刚关单了一笔 Meridian Core 平台交易，标记为赢单，按路由政策通知对的团队，核对客户层级表，需要的话换算货币，再查一下有没有没关的支持升级。

听着平平无奇，里面却藏着找政策、读表格、跨系统核对的连环动作。600道这样的题，最强模型答对四成，远没饱和。

Nathan 追问：给模型装上 Zapier 的工具能提多少分？Wade 说答案留给 Automation Bench V2，但方向清楚：给模型工具、降成本、提速，分数会涨。Zapier 现在的打法就是让智能体学会规划，哪些步骤直接写代码固化成确定性流程，便宜、可靠、可预测；哪些环节真需要判断，再调AI来推理。

那个80%的判断就来自这里。Wade 看了大量客户使用智能体产品的数据，结论是绝大多数场景在用大炮打蚊子。

「你只该让AI去推理那些真正需要推理的事情。公司生产流程里的大量工作，眼下就不该交给AI。」

他不否认AI在变强，但想不出一个确定性代码会彻底退场的世界：有些活，代码就是更便宜更可靠；有些活，代码干不了，那才轮到机器里的幽灵出场。好的智能体该学会分辨，别每次都架一个全程靠推理的智能体。

Nathan 原以为一个自动化流程至少要跑几十万次才值得配。Wade 纠正了他：上面那道关单路由的题，好公司每天都在发生，甚至一天多次。很多流程的触发频率高到人类根本跟不上，消费级业务一秒好几单，你没有任何选择，只能自动化，不可能往里塞人。

新的无代码，就是代码

这一集的标题就叫 No Code Is Code，来自 Wade 的一句总结。

「新的无代码，就是代码。」

让AI帮你搭流程，这件事本身已经过时了。但人还是需要可视化，一是验证，这东西跑的是不是我想要的；二是当文档，可以甩给同事看，这是我搭的，它在干这些事。

所以新的分工是：人跟智能体说话，智能体去搭、去改；流程固化成确定性代码在跑；跑挂了，智能体接手排查，用推理把流程修好。智能体接过了人建设和维护的活，真正干活的还是确定性流程，AI 只织在必要的位置。

排查这件事，Zapier 自己跑出了实战数据。他们的自动客服邮件程序，每次起5个独立智能体评估同一个故障，4个意见一致，大概率就是真问题。人工只做两件事：点赞，或者点踩加一句理由。理由回流系统，换个模型、换个提示词再测，人再审，循环爬坡。

这套循环攒下的东西，Wade 认为是 Zapier 护城河的一部分：15年自动化数据，连接一切的能力，用自家数据喂出别人抄不了的优势。他举了个例子：把 Gmail 接上模型，它写邮件立刻更像你，因为你没调教它，它看了你怎么写。接上公司数据，模型自动变好，这是当下最划算的技巧。

最大的对手，是还没用起来的人

Nathan 担心前沿实验室抢饭碗，自嘲 NotebookLM 都可能把他的播客节目端了。Wade 拿出 PG 在 YC 的老话：当年创业者夜不能寐的问题是「Google 要是做了怎么办」，但真刀真枪对上的，往往是某个冲着晋升来的中层产品总监，干两年就跳槽。

如今 OpenAI、Anthropic 已经是大厂，模型它们最强，但它们不可能什么都做。Wade 环顾四周的感受是，X 上所有人都在造所有东西，一片同质化的海；走出这个气泡，普通人用AI最多是搜索时顺手问一句 Gemini，或者公司配了个 Copilot。

眼下真正的对手，是「还没用起来」这件事。绝大多数用户压根不知道那些竞品的存在。而市场大得离谱，Wade 说自动化市场比他们15年前创业时设想的大了大概一千倍。

Nathan 也承认自己判断失误：五年前他以为整个经济体的工作方式会大变，结果收入暴涨的是模型公司，普通人的生活纹丝不动。Wade 的解法是别等用户开窍，把懂行的人「坐你旁边」的体验做进产品。

他自己的做法是每周跑一个自动化：让AI读他一周在 Gmail、Slack、浏览器、Cursor 里的活动记录，然后直接提议，这周你该搭什么工具、什么流程。坚持下来，他的工作里已经有大量环节在自动运转。这个体验 Zapier 打算做成产品卖给客户。技术上没走录屏路线，走的是API，理由很朴素：Zapier 擅长API，AI 读日志也比看录屏在行。

从首席人力官管AI，到月烧3万美元的账单

内部治理部分，有几个值得琢磨的操作。

第一，Zapier 让首席人力官 Brandon 负责 AI 转型。Wade 解释，第一阶段是全员扫盲，公司里没有AI委员会，也没有只让少数人研究、其余人照旧的安排，ChatGPT 发布后一年内，几乎100%的员工日常用AI，技术采纳早已不是瓶颈。瓶颈变成了人的问题：改职位描述、改薪酬设计、撤并团队、再培训。这些恰好是人力团队的强项。他特意强调别照抄，正确做法是看清自己的瓶颈，再挑对的人去啃，换一家公司可能是 CMO，也可能是 CTO。

第二，沟通默认公开。Zapier 本来就有「默认透明」的价值观，但公司变大后，一些工作溜进了私聊和小群。高管层搞了个友谊赛，看谁把沟通放进公开频道的比例高，没有考核惩罚。结果发现能公开的比想象的多，而且智能体看到完整上下文后，干活效果明显上一个台阶。例外当然有：HR 事件、进行中的安全漏洞，这些走私密频道，解决完再分享复盘。

第三，token 账单。Wade 发推说过，有工程师一个月烧掉3万美元 token。Zapier 约800人，目前没设个人预算，先做了仪表盘让员工自己看花费、对比强弱模型的价格差。看到大额消费，管理者的第一反应是好奇地问一句你在干什么，有人确实在干极高产出的活，有人只是选错了模型。Wade 预判 token 预算迟早制度化，AI 素养的一部分，就是会花钱的人配更大的预算。

定价的判断也顺势给出：按座位收费的时代结束了。智能是产品体验的核心成本，固定席位价撑不住，最终会滑向按用量或按结果计费。客服工具按解决的工单数收费，是结果计费的样板；多数产品离完整结果还差一两步，所以先按用量走。Nathan 追问要不要立法拉平 token 售价，毕竟订阅计划同等美元能买到约20倍的量。Wade 站在自由市场一边，公司有权定价，但他也提了微软当年靠捆绑挤掉更好产品的历史，各国自有判断。

安全部分，Zapier 替用户保管高价值凭证15年了。Wade 的判断是，前沿安全模型现在可以不知疲倦地循环扫漏洞，每个软件项目都有漏洞，只是还没被发现；模型让发现变快，也让修补变快，聪明的公司攻防两头都用模型。Hugging Face 那次事故，他说像科幻小说。Nathan 补了一个观察：能否进新模型的早期访问名单，可能成为托管凭证类公司的差异化因素，Wade 承认他们确实在争取。

人机合著的四条底线

Nathan 自曝，有些稿子没逐字重写，AI 检测工具 Pangram 直接判定是AI写的，Zapier 对外内容也有 Pangram 分数偏高的时候。这个话题绕不过去。

Wade 的态度很清楚：不反对用AI写东西，反对的是低质量。一个判断力不行的人，现在可以在极短时间内产出海量低质量内容，把读者淹没。他给员工立了几条规矩：

  • 对发出去的东西负责。作者花的时间应该比读者多，AI 不能变成把任务甩给读者的方式。
  • 要理解你发的东西。别人追问两句就露馅，那就不该发。
  • 把诉求写明白。要决策还是要反馈，是草稿还是定稿，标清楚。
  • 核实细节。AI 会幻觉，会拉旧信息，摘要套摘要传几手，错的就当真的了。

至于AI腔，满屏的破折号、那些口头禅，Wade 点名批评：营销材料里全是这种东西，读者会疲劳，很难出头。编辑的手要留在方向盘上。用AI没问题，低质量才是要打的那场仗。

组织形态的变化倒是比想象中温和。经典的工程、产品、设计三位一体团队基本消失了，管理层数在压扁，但强管理者更值钱，一个人管更多的人。数据分析师没被裁掉，只是都去做更高价值的事，因为每个员工现在都是自己的初级分析师。Wade 看到的方向是「造工厂的工厂」：软件工厂、支持工厂，流程管内环，人负责设计这台机器。

明天就能用的五件事

这期节目信息量大，能直接搬走的东西也实在。

  • 把工具的 MCP 装进你的驾驶座。Wade 最后的安利就是 Zapier MCP：如果你还觉得 Zapier 是屏幕上点框框的老古董，装进 Cursor 或 Claude Code 试一次，体验完全两样。
  • 给自己搭一个周复盘智能体。让它读你一周的邮件、聊天、浏览记录，直接问它：我该把哪件事自动化？然后让它去搭。Wade 每周跑一次，几个月下来大量杂活已经在替他运转。想法只要五成靠谱就值得启动，聊起来就会滚雪球。
  • 用80比20自查手头的智能体流程。需要判断的环节留给模型，重复执行的环节让智能体改写成代码，成本和可靠性都会改善。
  • 用AI写东西前过一遍那四条底线：自己负责、自己看懂、诉求明确、细节核实。
  • 检查一下团队的沟通有多少锁在私聊里。能公开的公开，你给智能体的上下文越完整，它干得越好。

Wade 在节目结尾说，18个月最大的心得其实很朴素：工具已经够好了，卡住大多数人的，是他们还不知道这些工具能替自己干什么。先让AI看见你的工作，它才知道从哪儿下手。
