《3 次语义错位，准确率从 99% 掉到 16%：Cisco 把多 agent 协作协议开源了》

一个五 agent 的系统跑起来，面板全绿，准确率 99%。出现一次语义错位，掉到 98%。两次，81%。三次，16%。

这组数字来自 Cisco Outshift 的 SVP 兼 GM Vijoy Pandey。他在《Cognitive Revolution》里给出了团队在生产环境里测到的结果。16% 比随机猜好不了多少，而监控面板上什么都没报警。

今年三月 Pandey 上这档节目时，讲的是「认知互联网」的愿景：agent 之间需要一套高阶协议，共享上下文、对齐意图、一起解决问题。半年多过去，Hugging Face 上那起 agent 越权事件已经成了公开案例，多 agent 系统也进了 Swisscom、ServiceNow、SoftServe、WebEx 的生产环境。连接做成了，认知没跟上。

Pandey 团队最近开源了三个项目：SCOPE、Accord、Concord。名字像法律文件，解决的问题很具体：agent 表面上在合作，实际上各说各话。

从孤岛到连接，只走完了第一步

Pandey 把 agent 的演进拆成三个阶段。

最早是孤立 agent，一个模型加一个 harness，自己跟自己玩。然后是 agent 孤岛，同一个 harness 里塞多个 agent，Hugging Face 那起事件里的协作就属于这一类，几个 agent 在同一个环境里自发分工，有人当协调者，有人当执行者。现在到了第三个阶段：连接 agent，来自不同厂商、不同云、不同组织，为了一个业务目标走到一起。

MCP 解决工具调用，A2A 解决 agent 之间的发现和通信，Cisco 主导的 AGNTCY 项目已经捐给了 Linux Foundation。这一层是连接的基础设施，过去一年基本铺完了。

问题出在连接之后。Pandey 的原话是：连通不等于共享认知。 agent 能互相发消息，不代表它们对同一个词的理解一致，也不代表它们在为同一个全局目标优化。

他把这个差距类比成人类语言的诞生。大约七万年前，人类发明了语言，才从个体智能走向集体智能。语言让人类能做三件事：共享意图、协调分工、把知识跨代累积。今天的 agent 有模型、有工具、有 MCP，个体能力很强，但还停在「发明语言之前」的状态。

面板全绿，任务完成率零

SCOPE 是三个开源项目里最底层的那个。它架在 OpenTelemetry 之上，把 agent 之间的交互 trace 拿过来，构建知识图谱，专门识别认知层面的失败。

Pandey 团队先用公开数据跑了一遍。ChatDev 是一个多 agent 软件开发环境，公开 trace 里 100% 的会话都存在语义失败和认知错位。不是偶发，是全部。

然后是他们自己部署的系统。一个订机票酒店的旅行规划用例，agent 全部在线，系统可用性 66%，仪表盘显示运行正常。但任务完成率是 0%。Pandey 的说法很直接：仪表盘是绿的，结果是错的。 他把这类问题叫「静默失败」，后果很响，只是没人听见。

准确率的衰减曲线更说明问题。一次认知错位，99% 到 98%，还能忍。两次，98% 到 81%，勉强能用。三次，直接掉到 16%。三次不算多，一个五 agent 的系统跑到中途出现三次术语或目标理解偏差，太正常了。

SCOPE 的定位像车道保持辅助。车在高速上跑，你走神了，轮子开始压线，系统提醒你回正。它盯的是认知漂移，一旦发现某个 agent 偏离了共同目标，就触发上层的对齐协议。

Swisscom 的数据中心，五个 agent 加一套形式化模型

Swisscom 是瑞士电信运营商，他们的用例是数据中心配置迁移。网络环境大到人脑无法完整建模，改一个地方，另一个看似无关的地方出问题，蝴蝶效应在基础设施里是日常。

Cisco 和 Swisscom 的做法是神经符号混合。符号那部分是网络的正式模型，相当于物理定律，agent 不能绕过。神经那部分是五个 agent，在符号约束内探索所有可能的配置组合。

Pandey 用下棋打比方。跟人下棋容易出错，跟深蓝下棋你赢不了，因为它知道每一步的所有应对。这套系统的目标是配置 100% 无误，不是 99%。 五个 agent 负责探索，形式化模型负责兜底，不合规的操作直接被拦。

为什么必须是多 agent？Pandey 的答案不在技术层，在组织结构层。企业里最有价值的问题，从来不是一个人能解完的。一笔两百万美元的订单要走完销售、法务、财务、产品工程、市场五道关，每个环节有专门的 agent，销售数据来自 Salesforce，法务来自 Harvey，工程来自云厂商的编码 agent，市场来自 Jasper。价值不在任何一个 agent 内部，价值在交接处。

一个估算可能变成承诺，承诺可能变成合同条款，合同条款可能变成市场宣传。每一次 handoff 都在放大或扭曲信息。全局结果只有在所有专家 agent 能真正协作时才存在。

Accord 管开工前，Concord 管开工后

对齐问题分三段：工作前、工作中、工作后。

工作前的问题叫术语和意图错位。销售说「十万用户」，工程理解成十万并发用户，客户可能指的是十万注册用户。一个词歧义，后面全歪。Accord 就是干这个的，开工之前先把目标、术语、范围对齐，写清楚再动手。

工作中的问题叫协调和谈判。销售拍了一个交付日期，工程理解成首个内测版本，客户理解成正式上线，财务关心的是合同什么时候签、钱什么时候到。需求还在变，功能还在加，客户看到东西又说不是这个意思。Concord 处理的是这种持续变化下的协商，目标是开工前定好的，路径可以边走边调。

工作后的验证协议还没发布。Pandey 说这是第三步，要确保交付的东西对得上当初对齐的目标，也对得上过程中协商调整过的范围。

这三个协议以 skill 的形式发布，可以直接插进 Claude Code、Codex 或者各种开源 harness，也可以通过 Agent Bridge 架在 A2A 和 MCP 之上。SCOPE 在底层做观测，发现漂移就触发 Accord 或 Concord 把 agent 拉回来。

你不需要换掉现在的环境。我们不想打断 agent 之间的通信方式，只想在它们认知漂移的时候，让它们回到正轨。

人类的位置也在变。Pandey 的说法是从「人在环内」变成「人在环上」。现在的 verifier 通常是人，未来判断力会被部分蒸馏进 agent，但最终问责的还是人。他提到 Raj Reddy 的分类：GAts 是守护天使，负责拦住不该做的事；COGs 是认知加速器，负责把已经想清楚的事快速复用。判断类 agent 更可能长成 COG，把过去做过的判断沉淀下来，不重复讨论。

两个 agent 订不了一顿饭

Pandey 自己有两个个人 agent。一个叫 Arnold Layne，取自 Pink Floyd 1967 年的首支单曲，代表他自己。另一个是妻子的 agent，叫 Lyra Belacqua，取自《黄金罗盘》。

两个 agent 要协作完成一件小事：两周后订一家餐厅，庆祝一个纪念日。做不到。

第一层卡在模型能力。第二层卡在 harness，Muse 这类个人 agent 框架每次发邮件都要确认权限，Pandey 说如果每步都要点同意，不如自己给妻子打个电话。第三层卡在协商，他有他的餐厅偏好，妻子有她的忌口和氛围要求，时间要凑上，位置要合适。两个 agent 手里都有足够信息，但就是谈不拢。

人类做这件事要五到十分钟，两个 agent 在已经部署到全球的 agent 栈上做不成。Pandey 拿这个例子说明：如果 agent 连两个人的一顿饭都协调不了，企业里那种五方参与的复杂交易更没戏。

他自己的 agent 架构值得看一眼。身份、人设、记忆是固定的，跟底层的模型和 harness 完全解耦。Arnold 今天跑在 Hermes 上，也跑在 Muse、Dots、Grok 和 Cisco 内部 agent 上，后端模型从 Gemini 换到 Haiku 再换到别的，身份不变。他的判断是，未来每个人都该有一个贯穿所有场景的 agent，而不是按访问权限切成两半，一半高权限低自主，一半低权限高自主。切分本身说明我们还在防着它。

latent space、奶牛和三个缩放轴

节目里 Nathan 问了一个尖锐问题：Hugging Face 事件之后，很多人对 agent 之间用高维隐空间通信更警惕了。token 能读的时候都监控不过来，换成人类看不懂的向量，怎么管？

Pandey 的态度很明确：这件事不可避免。药物发现、新材料、天气建模、金融建模，这些硬问题需要 agent 之间交换比自然语言密度更高的信息。他的立场是加速，但按引入新药的方式来加速。 该做的测试要做，该做的 canary 部署要做，不能抄近道。GAts 这类 guardrail agent 的存在，就是为了让底层技术跑在合规和安全边界内。

Nathan 还引了 Yuval Noah Harari 的奶牛比喻：奶牛不懂金融系统，但它的生活完全被金融系统支配。人类会不会变成那头奶牛，被自己看不懂的 AI 超级结构统治？

Pandey 的回答是，今天已经是这样了。他不懂高频交易的细节，但交易系统在跑。他不完全懂法律条文背后的立法逻辑，但法律在管着他。区别在于有专家懂，有记录可查，有系统可审计。SCOPE 这类工具的价值就在这里：每一次 agent 决策、每一次工具调用、每一次跨 agent 协商，都留下可追溯的记录。 出问题能 debug，合规能交差，系统自己发现偏离时能触发纠正。

关于 scaling law，Pandey 把计算的历史拆成三个轴。垂直缩放是模型变强，算法缩放是同样能力用更少算力，水平缩放是把节点连成系统。云就是水平缩放的产物。多 agent 系统是智能的水平缩放，如果 agent 之间不能真正一起推理，这个轴就浪费了。

他还提了一个更大的图景：网络连接的端点正在变。过去四十年连的是数据端点，现在连的是会思考的端点，未来还会连上量子计算、热力学计算、振荡计算、具身 AI。这些端点交换的东西不一样，网络本身也要重做。

明天就能做的事

这集播客的信息密度很高，落到操作层面有几件事可以直接做。

  • 先装 SCOPE，别急着优化 agent。 用 OpenTelemetry trace 跑一遍现有系统，看语义失败率。Pandey 团队在 ChatDev 上测到 100%，在旅行用例上测到 66% 在线、0% 完成。你的系统大概率也有静默失败，只是仪表盘没告诉你。
  • 检查多 agent 系统的 handoff 点。 价值在交接处，错误也在交接处。一个术语在第一个 agent 那里被理解歪了，传到第五个 agent 可能变成完全不同的任务。把每个 handoff 的输入输出对齐一遍。
  • 开工前强制对齐术语。 Accord 的核心动作很简单：把目标、范围、关键术语写下来，让所有参与的 agent 确认。十万用户是总数还是并发，交付日期是内测还是上线，这些歧义在开工前解决，成本最低。
  • 把身份和 harness 解耦。 Pandey 把 agent 的人设、记忆、权限跟模型和运行框架分开，换模型不换身份。这样你不会被单一供应商锁死，也不会每次换模型就丢掉积累的上下文。
  • 接受「人在环上」的定位。 判断力暂时还在人这边，但人的角色从每一步确认变成关键节点拍板。如果 agent 每发一封邮件都要你点同意，这套系统还不如不用。

Pandey 最后说了一句话，值得记下来。今天的 agent 既能当奶牛也能当人，在一个多 agent 系统里，每个 agent 对另一个 agent 来说都可能是那头弄不懂全局的奶牛。区别在于系统有没有留下记录、有没有人看得懂、有没有机制在偏离时把它拉回来。这三件事，今天就能开始搭。
