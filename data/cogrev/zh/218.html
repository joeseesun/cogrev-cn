《不碰客户一行数据，回答准确率超95%：Illumex 想把软件界面收进一个对话框》

先看几个数字。一家典型企业客户的数据栈里，压着几百万张表：本地的 Oracle、SAP、Teradata、Vertica，云端的 Snowflake、Redshift、Databricks，再加上 Tableau、Power BI 这类 BI 工具。几十套系统，每个部门一套口径，没有单一事实来源。有个部门想等一块 BI 看板，排了9个月的队还没排上。

Illumex 的接法只花几天：只读元数据，不碰任何一行真实数据。之后员工在 Slack 里问一句"现在库存还剩多少"，几秒出答案。常用数据上的回答准确率超过95%。

主持人 Nathan Labenz 给了个参照系：把一个临时问题丢给大公司的数据分析师，一次性答对的概率，他自己的体感在90%到95%之间。机器的上限比人还高一点。

这期 Cognitive Revolution 的嘉宾 Inna Tokarev Sela（英娜·托卡列夫·塞拉），是 Illumex 的创始人兼 CEO，2021年创业，之前在 SAP 和 Sisense 做了多年数据产品。数学出身，第一个学位期间就在 MATLAB 里手写图算法，前后读过5个学位。公司主页上那句话是她的全部野心：让数据用员工说话的方式开口。

无应用未来：软件超新星的另一面是黑洞

她2021年去见深科技投资人，讲"为智能体自动化上下文与推理"，讲了两三场就发现没人懂，只好换成大白话：让知识工作者对结构化数据实现自助分析，走向无应用的未来。当时 GPT-3 只露出一点苗头，她判断时间到了的依据，是2017年之后语义模型和 Hugging Face 生态的成熟。她真正想解决的是个老问题：企业砸了重金建数据团队，大多数业务决策依然靠估算。她不怪任何人，人脑里的问题太多，此前从没有一个助手能自动用数据回答所有问题。

Nathan 把两种软件未来摆在一起对比。Bolt、Lovable 这类平台代表"软件超新星"，应用会爆炸式增长，人人都有定制应用；Illumex 代表另一种，软件黑洞，界面塌缩到一个点。他个人更向往后一种：摆脱椅子，走到户外还能处理信息、执行操作。OpenAI 的语音模式离这个体验还差着一截。

Inna 认为两者并不冲突。业务人员有正职，没工夫学新工具、来回切换上下文。她现场演示了手机 Slack 里的对话：问库存还剩多少，系统自动匹配后台的语义本体，返回数字。产品有两个模式，"让 Omni 决定"是自动驾驶，数据型用户可以切手动，点进语义实体看血缘、属性、定义，一路看到 SQL 代码。

"这是一个给控制狂准备的平台。多数人拿到答案就去行动，少数人想看业务本体和定义，可以一路挖到底。"

她自己戴着带扬声器的 Ray-Ban 智能眼镜，说这种体验是解放。她对终局的判断：所有交互最终会收敛到一个启动器，你说出问题或任务，事情就发生，背后调了哪个应用、哪份数据、哪个流程，你不用关心。整个工作站退到后台。

柏拉图式企业模型：几天读懂几百万张表

技术路线是这期最硬核的部分。Illumex 先为每个行业建了一套理想化的规范本体，覆盖电商、制药、制造、保险、金融、IoT，把同类企业共有的术语、流程、指标、依赖关系，封装成知识图谱加语义嵌入。Nathan 管这叫企业的柏拉图理念。

接入新客户时，系统拿这套行业基准当模板，只用客户的元数据重新训练：schema、查询日志、API 签名。几天之后，客户就得到一份专属本体。不要求人工标注，不要求把数据搬进向量库，本体是一层虚拟层，数据原地不动。系统还内置了跨系统的对应知识：这张表里的订单 ID，就是另一个系统里的供应商 ID。

Nathan 追问了一个尖锐场景：客户把"产品变体"命名成 VARX 这种无意义缩写，怎么办？

她的答案：语义再明显也不全信，用法才是铁证。系统除了建本体，还建分类学，记录每个元素的使用语境。一个无意义的列名，如果同时出现在两条计算里，而这两条计算都能映射到行业指标，就能反推出这个列是什么。前提是有使用日志；全新仓库没有历史，就靠语义定义的邻近度和数据管道的喂给关系来推断。

Nathan 提了自己踩过的坑。他的公司做小企业视频生成，试过用标准嵌入匹配模板，结果占位文本主导了匹配，想要的节奏和气质完全匹配不上，最后干脆放弃了嵌入组件。Inna 的回应是，结构化数据天然缺上下文，必须靠元数据和用法补；Illumex 的做法更狠：客户本体里凡是匹配不上行业基准的概念，一律删掉，绝不引入客户数据里没有依据的业务概念。

她还主动提了 Palantir：这套思路不新，Palantir 也有业务本体加映射流程，区别在于 Illumex 把映射做成了全自动。基准测试用了学术数据集 Spider，覆盖从棒球到烹饪大约60个领域，每个领域上下文极少。Illumex 给所有版本自动建本体去跑，准确率91%。没到99%的原因查过了：开源数据集里有垃圾，部分标注本身就是错的。真实企业场景里上下文远比 Spider 丰富，成绩只会更好。

不信语义信用法：几十个小模型各管一摊

一个反直觉的架构选择：Illumex 没有微调一个全能大模型，而是让几十个语义模型和图模型分工。显式语义标注一个，SQL 查询解析一个，语义实体消歧又一个，再配上图神经网络和传统子图匹配算法。每个任务单独跑基准，他们至今没找到任何一个开源模型能通吃所有任务。

新模型发布，他们的动作是马上测。结论有点扎心：通用大模型在公开语料上越来越强，但对私有业务语料的理解至今没有实质突破，因为基础模型追求的是最大公约数。意图理解在进步，比如"show me"能推断出要计数，可一旦涉及企业内部语境就失灵。

变化也是真实的。以前解析一条 SQL 查询要动用一整个模型集成：分解查询、分类过滤器、识别度量，各管一段。现在一个在自有语料上训练过的简单语义模型，性能超过了原来的集成。还有跨行业本体的互相"授粉"：供应链公司问"今天有多少 pieces"，系统知道这里的 piece 指交付。行业黑话之间的映射，靠本体在不同行业间的投影完成。

系统还在持续学习。它自动吸收所有历史人机交互，相当于一个集齐了公司全部分析师经验的超级分析师。逻辑漂移的处理很谨慎：新旧逻辑冲突时不直接嵌入模型，先标记为冲突，交给数据负责人裁决。可以设自动阈值，比如偏差超过20%就自动吸收，但客户实际都选择先人工看一遍。她的总结：听起来复杂，用起来只是审阅，因为上下文和推理已经预建，整体省掉90%以上的工作量。

可以审问到死的系统，和必须签字的人

准确率的细节再展开一层。常用数据上超过95%；冷门的历史数据上略低于95%，但系统返回"无答案"时，100%是因为数据本身坏了，缺值、重复、同一数据在不同系统里分布不一致。这种诚实的不回答，恰恰是企业数据场景里最值钱的能力。

自动生成的本体要过一道人工认证，业务用户在网页界面或 Slack、Teams 里确认定义。她的理由很直接：你不信任供应商，就没办法信任系统的输出。对比人类分析师，她有个说法很有画面感：人类分析师被追问三次"你为什么用这个口径"就会烦躁，机器可以审问到死。问渠道归因怎么算的，系统会答：这个定义来自你的业务指标库，这个数据源被90%的 API 调用使用。追问一两次，搞懂逻辑，业务人员就敢基于数据拍板了。

"香肠的制作过程没人想看，蛋糕怎么烤出来的却必须透明。这个类比是故意的。"

治理是内置组件：自动审计冲突、重复、PII，报告可导出。接口层也封死了：每次提问都被映射到业务本体的一部分，业务人员没法从聊天框重写组织级业务逻辑。逻辑变更只有一条路进来：底层系统的元数据变了，加表、删表、换 API，系统标记、告警、自动生成新定义。运行时也做了切割：Illumex 只生成查询，发给客户环境执行，结果回到提问的界面，全程不碰数据值。

死守元数据，是创业早期的主动选择。当时的客户调研电话里，企业一听 SaaS 要用生成式 AI 碰他们的数据，基本就没戏了。她的逻辑是：同一家供应商既握着你的业务逻辑，又握着你的数据值，这是巨大的风险敞口，降低客户风险是第一优先级。有人问她作为女性创始人是什么体验，她的回答很干脆：这就是我唯一的体验，没有参照物。而现在，供应商安全问卷里的一大半问题，元数据方案直接跳过了。

省下80%token，按数据源封顶收费

商业账很清楚。上下文和推理预建之后，大部分调用在内部消化：请求先匹配预建过滤器，匹配上了才发起运行时调用，最多省80%的 token 成本，比每次都把上下文塞给大模型便宜得多。

这套预建上下文还有更大的野心：智能体编排。她的判断是，行业正从单点智能体应用走向跨模型工作流，每个模型如果各揣一套上下文，永远对不齐，共享上下文是编排的前提。Illumex 的上下文格式可插拔，接 AWS Bedrock、NVIDIA NIMs 这类运行时，客户可以用不同厂商的智能体模型搭工作流，全部对齐在同一份上下文上。

定价也顺着这个逻辑走。按席位收费在智能体时代会失灵，一个高管的 AI 助理一天可能发起上千次查询。Illumex 按数据源数量封顶收费：1个数据源是入门包，3到5个是中型，企业级全包，不限席位不限用量。她引用投资人的说法，要可预测性；又补了一句行业观察：去年企业 AI 采用放缓的最大因素，就是成本和 ROI 的意外，圈子里管这叫"AI 成功的成本"。

用户构成的变化，她给了个时间刻度：6个月前，主要用户还是懂数据的人，数据管理、治理团队、分析师，拿它查自己不熟的领域；最近6个月，所有进来的需求都指向业务人员自助。她预计下一个用户群体是智能体本身，AI 助理在 Slack 里直接找 Illumex 对话，这一天比所有人预想的都近。

数据是新的护城河，分析师去当审核员

Nathan 问了个好问题：元数据算企业的脚手架吗？竞争对手拿到它，会不会比拿到原始数据还值钱？她把话题拐了个弯。流程和指标大多要公开披露，差异化不在那里。她给出的判断是：基础模型会越来越快、越来越便宜，围绕它的自动化会像你的数据一样个性化，企业真正的差异化是多年积累的数据厚度。不把能攒的数据都攒下来的公司，是在错过下一个收入引擎。五年前人人说"每家公司都是数字公司"，接下来轮到数据产品、数据服务，甚至数据智能体，直接卖给客户和合作伙伴。

Nathan 又问了个残酷的问题：今天的大学生该不该学数据分析？她的回答分两层。SEC 报告、董事会报告这类带法律责任的东西，短期内必须有人签字，分析师不可替代。真正被解放的是另一群人：那些排了9个月队等 BI 看板的部门，公司没预算建看板，配一个数据副驾驶却是明天就能做的事。她从头到尾强调的词是增强。

职业形态会变：内容创作者变少，内容审核者变多。她类比从拉马车到开车。她算了笔账：现在企业在数据分析上的投入，只做了这个领域10%能做的事。升级后的分析师该去处理告警、裁决冲突、给软件下指令、跟业务用户对齐预期。新人得先在一个领域扎得足够深，才能快速胜任审核角色。人类的价值在于懂类比、懂隐喻、懂客户意图，能看出"为什么这个模型报数据不足"，因为见过语义系统一轮轮的迭代。

聊到怎么跟上这个领域，她的答案又一次反直觉：灵感来自产业界，学术界跟不上。她读学术文献，提到一篇发表在顶会上的供应链本体 RAG 论文，证明了行业本体能让 RAG 更好也更便宜，但每个场景手工建本体不可扩展。她建议盯大厂的动向，包括 DeepSeek 这种意外来源，商业主题演讲里信息量很大，只是需要读出言外之意。Nathan 补了一句自己的观察：当今最好的通识教育，往往来自那些跑得快的网络实践者，头衔不显赫，但始终贴着前沿在做东西。

节目的结尾落在她9岁的儿子身上。她早早教孩子用 ChatGPT，教的是批判性思维和查证来源。孩子现在的态度是：作业太简单了，我自己写就行。她读过5个学位，如今的说法是，人生苦短，技术跑得太快，先上手摸最新的东西。

整期听下来，能直接搬走的东西有四条。

  • 评估任何"AI 查数据"产品，先问三个问题：看不看我的原始数据？本体谁认证？逻辑冲突谁裁决？Illumex 给出的答案分别是：不看、业务专家、数据负责人。答案含糊的产品，慎入。
  • 别急着把 schema 粘进 ChatGPT 就当数仓用。先梳理查询日志和 BI 报表里的既有口径，这些元数据是现成的上下文，对答案质量的影响比模型本身更大。
  • 给团队选 AI 工具，定价看封顶不看单价。按席位和按 token 计费，在智能体时代都是意外账单的来源。
  • 如果你是数据分析师，把重心从写查询挪到定口径、审逻辑、管告警。机器接手的是取数，接不走的是"这个指标到底该怎么定义"的话语权。
