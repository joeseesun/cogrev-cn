《Google Docs 前身作者，用 15 个自造工具给自己装了道注意力防火墙》

Steve Newman 的收件箱，每天早上会多出大约 50 篇长文。Substack、博客、新闻通讯、播客，全算上。再加上 Twitter 时间线和几个活跃的 WhatsApp 群，邮件、Slack、WhatsApp 这类消息一天几百条。

他统计过自己的动作：大脑每从一个任务里探出头来，就去轮询一遍手上的 5 个应用，一天差不多 30 次。绝大多数消息不用立刻看，但总有几条真的急。

这位从 1985 年写代码写到今天的工程师，最出名的作品叫 Writely，2006 年被 Google 收购后改了名，就是现在的 Google Docs。上一家公司 2021 年被收购之后，他把晚上和周末全投进一件事：用 Claude Code 给自己造工具，如今挂着大约 15 个项目。他的正职是去年联合创办的非营利组织 Golden Gate Institute for AI，旗舰活动是年度大会 The Curve，350 人规模，今年定在 10 月 2 日到 4 日；Substack 专栏 Second Thoughts 在 AI 圈子里以克制、不贩卖恐慌、偶尔坦承「我也不知道」的风格攒了一票忠实读者。

在 Cognitive Revolution 这期节目里，他把整套工具箱摊开给主持人 Nathan Labenz 看。Nathan 自己也搭了几个月的 Claude Code 生产力栈，看完的原话是，一路好几个灯泡时刻，原来自己还留着这么多价值没捡。

注意力防火墙：急事自己找上门

工具箱的核心是一件叫 Radar 的东西，名字来自老剧《陆军野战医院》里的通信兵 Radar O'Reilly，永远赶在你开口之前把你要的东西递过来。

原理说穿了不复杂。Gmail、Slack、Signal、WhatsApp 的消息全部拉进来，每条丢给大模型问一句：这事急吗？判断标准是一页纸的 rubric，一条条例外慢慢攒出来的。判定为急的，弹到第二块屏幕上。

为了这块屏，他打破了自己 40 年的坚持，人生头一回买了第二台显示器。屏幕上是滚动视图：三小时的日历，加一条紧急消息列表。这套东西的目标只有一个，除了他当下专注的事，他只需要看这一块屏。

日历也重新裁剪过。占位用的封锁时段不显示，妻子的日程过滤掉，内部例会直接配三个按钮：进会议、开私人笔记、开共享文档。转发键默认转发给妻子，因为家里的 Amazon 和 PayPal 账号共用，很多通知其实她才关心。

安全网也留了。所有原始消息都待在原地，Gmail 还在 Gmail，Radar 做的只是改标签。系统就算整个崩掉，损失的只是界面，数据一根毫毛不少。

15 个项目：工具好造，集成难啃

信息过载是第一个主题。他最早造的是个 RSS 阅读器，订阅源抓进来，每篇预生成两层摘要：一层一段话，10 秒扫完，决定读还是不读；另一层一页纸，明确要求标出新观点和关键证据，是他不读原文时的八二开替代品。Opus 4.7 发布那天，几十篇文章讲同一件事，扫一遍摘要就知道哪篇有新角度。

  • Hacker News 讨论串分析器：自动读文章、读全部评论、归出主题，点开某个主题看这一类评论。HN 讨论串里精华和噪音缠在一起，这个工具负责拆开。
  • Chrome 扩展：每次加入 Google Meet 要点 5 个按钮，切账号、藏掉自己的窗口、确认摄像头。他写了个扩展一键点完，每次省 15 秒，一天三次，写它花了几分钟。
  • 编码 agent 状态面板：蓝灯是干完了一个任务，红灯是没活干但待办清单里有它的条目。点一下直接跳到对应终端标签页。背后是 Claude Code 的 hooks 上报状态，再用一个叫 Hammerspoon 的 macOS 工具粘合，那工具是 Claude 让装的，他自己也没完全搞懂是什么。
  • 垃圾邮件文件夹重排：不按时间，按列排序。他常收到发给 me@aol.com 的信，那地址根本不属于他，一排下来整块跳过。

集成是所有项目里最磨人的部分，八个数据源八种方案。WhatsApp 的解法最妙：桌面版在 Mac 上同步消息时，会存进一个未加密的 SQLite 数据库，他直接读这个文件，cron 任务一分钟跑一次。只读，不碰内部 API，WhatsApp 无从知晓，也就没有封号风险。那些主动调 WhatsApp 内部接口的方案，社区里封号故事不少。Claude 在数据库 schema 里反复探洞，才搞清楚哪条是回复、哪条是原帖。

Twitter 是最糟的一个，靠一个来路可疑的第三方服务，手动轮询大约 80 个关注对象，一小时轮一遍，再快费用就肉眼可见了。Nathan 告诉他 Twitter 刚推出按量计费的官方 API，他当场表态：这方案下次一坏就换。

所有应用都往一个自建日志服务里写，SQLite，放在 Cloudflare 上。后端写，浏览器前端的 JavaScript 写，Android 应用也写，Claude.md 里塞满咆哮式规则。出了问题他只说一句 debug this，配合 Jesse Vincent 的 Superpowers 插件里的 systematic debugging 技能，Claude 会去翻日志找证据，被反复叮嘱过不许猜。他给出的唯一一条「只做一件事」级建议：让所有部件的日志汇到一个地方，包括前端，然后用力提醒 Claude，你不用猜，你可以去看。

工程组织上，15 个项目各占一个 GitHub 仓库和一个 Cloudflare 数据库，故意拆小，好让 agent 的上下文装得下。所有 Claude Code 会话跑在 Mac 的 Docker 容器里，开着跳过权限确认的模式，项目目录并排摆放，agent 之间能互相看代码、互相调 API。没有 staging 环境，永远直接推生产，赌注押在「数据都在原地」这条安全网上。

「agent 不重要，我才重要」

圈子里流行一种说法，要让 agent 吃饱，别让它闲着等你，业内管这叫 token maxxing。他认真掉进这个坑一两个月，压力很大，然后想通了。

agent 不重要，我才重要。我优化的是我自己的时间。

早期确实做不到。只有一个项目、一个 agent，他的时间大量耗在等 Claude 上。拆成 15 个项目之后，等待消失了：这个 agent 在跑，他就去给下一个准备 prompt，或者扫一遍摘要队列。高峰期他一周花 15 到 20 小时写代码，现在大概一天半小时，同时挂 0 到 5 个 agent。

散步是同一个逻辑。他常出门走路，为了身体，也为了换脑子，走路时不追求多塞几个 prompt。想清楚一件事，掏出手机，打开 Gmail，给自己写一封邮件，用键盘自带的听写按钮把脑子倒空。回家把这段脑倒粘给大模型，一句话，整理成 Claude Code prompt。他通常连整理结果都不看，直接让它跑，跑偏了再纠正，比通读三页整理稿省事。

花费上，Claude 和 ChatGPT Pro 都是每月 200 美元的档位，30 美元一档的额度最近一周要充两三次，写代码的开销全在订阅内。给文章生成摘要这种活他直接用 Opus，理由是反正不贵。Codex 他一个月前试过一次，一个 prompt，表现糟糕，他自己承认那不算公平测试，只是 Claude 够用，就没了换的动力。

还有一条会让职业工程师皱眉的：他从不打开代码文件。这 15 个项目全是 TypeScript，他不会 TypeScript。他看的是 Claude 的高层决策，帮它避开几条歧路，然后几乎从不回滚。

安全这道题，他承认没答案

工具箱里所有东西都只读。他不许 agent 替他回邮件、替他行动，理由是天性保守，不信任的工具不用。他引《夺宝奇兵》里那句台词自嘲：毒蛇很危险，你先请。

矛盾摆在那：每份新模型报告都说 prompt injection 抗性又降了几个百分点，可所有人都同意，把任何重要东西交给这套系统都不可信。这个张力怎么解，他说自己看不懂。

更大的谜团是，AI 钓鱼诈骗为什么没爆发。他举了 1982 年的泰诺投毒案：往货架上的药瓶里掺氰化物，这事几十年里任何人任何时间都能干，只发生过一次，后果是全世界的产品从此多了塑封。可网络安全又有反面案例，一台不打补丁的 Windows 接上公网，几分钟内沦陷，这是几十年前的老统计。两种规律怎么调和，他坦白说不知道，谁想明白了请告诉他。Nathan 补了个猜想：AI 用得好到能高效骗人的人，正大光明赚钱可能更容易也更稳。

Nathan 还提到一层责任。他那个用了 20 年的 Gmail 里，存着所有人当年托付给他的话，他们按下发送键的时候，可没想过这些话会进一个当时还不存在的 AI。这份责任让这个历来对安全漫不经心的人，第一次慢了下来。

模型很惊艳，AGI 还很远

聊到两人都还没摸到的新模型 Mythos，以及 Nicholas Carlini 那句「几周找到的漏洞比过去整个职业生涯加起来还多」，Steve 给出了他标志性的两头不讨好立场。

舆论场里通常只有两个阵营，要么模型神了基本到 AGI 了，要么模型毛病一堆 AGI 还远。他的答案是第三种。模型很惊艳，同时 AGI 仍然很远。Carlini 那种表现，他给模型记 300 分，所有事上都比人聪明值 50000 分，大家忘了差距还有多大。他引用 Helen Toner 的话给自己留余地：长 timeline 已经不是过去那个意思了，还有段距离，如今可能只意味着五年。

他承认论证有个软肋：我们从不让 AI 做它做不到的事，所以看不到它做不到什么。他举的例子自己都觉得蹩脚，AI 没法替他去和妻子吃顿晚饭聊场天。找不到好例子这件事让他怀疑自己是不是在瞎说，但直觉还在。

关于递归自我改进式起飞，他列了三个没想明白的问题。第一，造模型的完整技能清单长什么样，设计 RL 环境的老手比新手强在哪种细微的品味和判断，自动化 AI 研发是一年内的事，还是中间藏着硬骨头。第二，超人类的编码和数学能力，能不能顺滑泛化到营销、战略、教学、产品这些模糊领域。第三，机器人是再来一个 Rodney Brooks 式的几十年，还是超级智能直接碾过去。Waymo 算存在证明，他坐上去比把方向盘交给自己或旁边的司机都踏实，但那用了几十年，而且汽车只有两个自由度，快慢加左右，一根手指头的量级。

解释变化为什么总在某个时刻突然爆发，他用了冠状病毒的类比。R 值 0.9 的病毒偶尔跳到人身上，传两三个人就熄灭，某天出现一个 1.1 的，整个系统翻进新域，这就是相变。他的 Substack 里写过，AI 的影响是八个因子的乘积：预训练、后训练、推理算力、agent 脚手架、应用设计、用户能力、工作流重构、采用率。ChatGPT 发布是一个时刻，去年 12 月一大群人因为 Opus 4.5 加圣诞假期同时开始 Claude coding，也是。能力曲线早就到位，差的是有人恰好做了那件被看见的事。

复盘 2021 年那场收购后的重建，把一家准备上市的公司底层查询引擎整个换掉，每天吞进数万亿条事件，他说最确定的一点是，生产系统本身今天还不敢 vibe code，但围绕它的调查早该交给 agent。当年为了做成本预估，团队要摸清客户的查询模式，没人说得清，只能手动翻日志跑查询。放到今天，就是让 Claude 写 100 个工具，跑 100 组调查，交 100 份报告再汇总成一份，全程不碰生产。

行业判断上，他看到一个正在收紧的拉锯战。他的工具箱里已经没有几个 SaaS 应用的位置，Gmail、Slack、WhatsApp 都退成了后端服务，他花在它们界面上的时间越来越少。平台方想把你锁在自家应用里，Slack 讨论过收紧 API，Amazon 在限制购物 agent，用户想要的是最好的 agent，管它是不是官方的。基础设施例外，S3 和 Spanner 这种数据底座，离被个人 vibe code 取代还远得很。招聘标准也在变，他说现在真正需要的是能没有地图走路的人，几十年攒下的最佳实践全作废了，而且沟通能力的权重在上升，因为过去一个团队的活现在归一个人，每个人都在做过去一整个团队的协调。

气候他承认看错了一半。没料到数据中心扩张这么快，也没料到超大规模厂商在抢电大战里集体后退，xAI 的 Colossus 数据中心直接运燃气轮机进场。但长线他仍然偏乐观，AI 推进的材料科学会解决电池，会把一堆石化工艺换成电化学工艺，机器人精准施肥杀虫省下的排放，可能超过数据中心多烧的电。他的总结是，AI 在给整个世界掷骰子，气候跟着坐这趟车，方向未定。

明天就能抄的作业

这期节目没有惊天动地的技术，全是今晚就能动手的东西。挑几条最直接能搬走的：

  • 把所有工具的日志汇到一个地方，包括前端，然后在 Claude.md 里写死一条：出问题先看日志，禁止猜测。
  • 给自己造一块第二屏：日历加紧急消息列表，规则随心定制，转发键默认给谁都可以。
  • 遇到社区爆火的新工具别急着装，先让 Claude 去侦察一遍，把好点子搬回自己的体系，顺带过一遍安全审查。
  • 大项目拆小，一个项目一个仓库，上下文好管理，agent 之间还能互相看代码。
  • 给高频小动作造界面。Steve 的判断是，现在的 agent 工具全是「动词」，你扔命令过去，大任务很合适；每天几十次的碎动作，值得一个自己写的「名词」，一个按钮。Nathan 录完这期的反思就是，自己造了一堆 skill，却几乎没给自己造过一个界面。
  • 把这期文稿丢给自己的 Claude Code，让它挑出对你现有配置最有用的几条。Nathan 录完当天就这么干了。

最后是那条心法。Steve 干了一辈子量两次裁一次，动手前把问题想透。现在他认为这套彻底过时了，直接上手、做错、扔掉、重做，才是这个时代的正确姿势。该改的是让工具适应你的工作流，别再反过来。
